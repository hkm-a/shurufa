# Shurufa 迭代方向（更新思路）

本文来自对搜狗输入法官方升级日志（PC 版与手机版在 2024-2026 年的迭代轨迹）的整理，并结合 Shurufa 目前的能力现状（Windows TSF + librime 雾凇拼音 + Android 输入法 + 跨设备剪贴板）提出一份可作为路线图参照的迭代方向。

生成时间：2026-08-08

---

## 摘要

搜狗近 2-3 年的升级集中在四个维度：

1. **候选与打字策略**：候选条/翻页/光标/首屏位置；多少候选、如何对齐习惯键盘位置。
2. **AI 与写作辅助**：AI 帮写、续写、润色、纠错、语意翻译、语音模型的持续升级。
3. **跨设备与多模态**：剪贴板跨设备复制粘贴（文本/图片/文件）、手机/平板/电脑的流动性。
4. **外观与个性化**：皮肤、主题、键盘布局、右上角指示灯、自定义工具栏；让专业与轻量用户都能找到自己的生活风格。

Shurufa 若在这四个维度分层推进，则可以把当前 Rime/librime + 剪贴板同步的骨架，逐步演化为更像搜狗/讯飞那样的“输入助手”体验，同时保持开源、可自建、无后台广告数据收集的差异化定位。

---

## 一、打字体验：候选词、翻页与光标（最高优先级）

### 1.1 候选页容量与层级化
- 参考：搜狗手机版“候选条精简”“多行候选/翻页布局切换”，搜 Dog PC 版“候选条界面重构”“下方翻页/更多候选用上下翻页”。
- 方向：
  - 在现有 `page_size=5` 的基础上，逐步加入“候选上下文”概念：当前行展示 + 下方备选的候选项聚类（同音同形/词语联想/表情/翻译候选）。
  - 允许长按候选条某个条目弹出菜单（复制、删除、加入自定义词频模式）。
  - 候选分页里引入“上次使用的候选队列”概念（不只按词频绝对排序，也考虑最近输入上下文）。

### 1.2 光标插入与位置编辑
- 参考：搜狗版对“点击拼音中间插入字符”这类长期的老bug从没有明确日志，但该功能外网存在已久；它偏底层，需要拼音拆解、引擎光标在 raw input 上的精准映射。
- 方向：
  - 当前已新增 `set_caret_pos` 原生精准插入；后续可扩展信息视图，在 preedit 上渲染“拼音分词视图”（如 `ni hao` 拆成 `ni / hao`），并提供候选内导航（Ctrl+左右/Tab/Shift+Tab）定位到某一音节上。
  - 引入“光标上下文候选”概念：当 preedit 相同但上下文不同的场景（如聊天、邮件、代码）中点亮不同的候选分级与展示策略。

### 1.3 切换与信号指示
- 参考：搜狗“Shift 切换中英文”“中英全角符号；大写锁提示；CapsLock 指示灯”。
- 方向：
  - 补充 `nativeIsAscii`、`nativeToggleAscii` 到 UI 反馈，候选栏对应显示“当前中/英文”。
  - 长按 Shift 进入大写模式（类似手机双击 Shift）；在键盘上对应加一个 Shift 状态指示。
  - Windows 平台要解决中英文混合输入时的流畅度（如快速连续中英文切换到的空格与时序控制），避免候选条残留旧切换状态。

## 二、AI 与写作辅助（选择性推进）

### 2.1 写作风格工具（非侵入式）
- 参考：搜狗的“AI帮写”“高情商回复”“灵感语录”“AI划词翻译”。
- 方向：
  - 这部分能力不建议直接取代当前 Rime 候选；建议做成**辅助视图**（如 `Ctrl+Shift+W` / 手势呼出面板 / 特定场景自动弹出）。
  - 实现路径：先用开源/本地模型（如 Ollama / llama.cpp / 用户自选 OpenAI API）接入，让用户自选模型是本地或远端。
  - 在 Shurufa 上记录词典：把高频写作短语（成语、新闻俚语、机构名）作为可选自定义数据包导入，不干扰词库本身的稳定性。

### 2.2 语音输入与语音纠错
- 参考：搜狗手机版持续强化语音（MV、网格、识别更准；离线环境可用）。
- 方向：
  - 当前的 Android 端语音模块和剪贴板服务可以合并：语音输入的临时结果直接进剪贴板，作为一个“语音哥白尼”功能（快速语音+粘贴到任意框，类似飞书的复制模式）。
  - 为用户提供“常用口语转为规范书面语”的切换（让语音结果不仅仅是原样转写，还可选“规范化”修饰）。

### 2.3 拼音之外的输入方式
- 参考：搜狗拼音支持双拼、五笔（企业版/开源兼容）、辅助码。
- 方向：
  - 如果现有 Rime 方案支持，则增强对双拼/五笔等输入法入口的支持，使其在 Shurufa 框架下可以平滑切换，不是替代而是补充。
  - 在输入语言与引擎的开放性上，保持与 Windows、macOS 原生输入法的兼容性。

## 三、跨设备同步与剪贴板（强化现有优势）

### 3.1 剪贴板层的稳定性
- 参考：搜狗“跨设备复制粘贴”（文本/图片）、变态、一键两端切换发送等能力。
- 方向：
  - 现有 `ClipboardSyncService` 已有同步框架，下一步强化：
    - 失败重试 / 离线缓存 / 重新注册时机（如设备恢复 Wi-Fi 时）。
    - 同步超时、冲突策略（不同设备同时复制不同类内容时可指明使用哪一条）。
  - 引入更明确的“发送来源标签”（当前仅为“本机/同步·Peer”），让用户知道内容来自哪台设备，避免错误操作。

### 3.2 跨设备界面
- 参考：搜狗“Android 工具栏自定义”“剪贴板排版多样化”“历史记录 UI 聚合”。
- 方向：
  - 当前 Android 端的历史面板/预览键盘已有基础；可以增加“历史筛选（按来源设备/消息类型/收藏）”“跨设备搜索”。
  - Windows 控制中心逐步整合剪贴板历史管理（现有 UI 已有）与多设备同步（配合现有 relay），将设置和日常操作模块化。

### 3.3 同步与隐私
- 参考：搜狗支持跨设备但是部分广告/数据隐私正在凸显。
- 方向：
  - 保持 Shurufa 的独立自建定位：支持私有导航服务器、自托管、可配置的策略（不开启数据收集），把“同步”作为开源卖点。

---

## 四、外观、皮肤与个性化（中等优先级但提升感知）

### 4.1 皮肤与主题
- 参考：搜狗皮肤标识、自定义键盘布局、换面板/换颜色的机制，长期在桌面和移动端存在。
- 方向：
  - 当前 `schemas/shurufa-skin.json` 是跨端皮肤入口，可以扩展为“主题包”：支持下载、商店机制（用户可自行上传/复用），让用户可基于 JSON 统一调整。
  - Android 侧可以增加“布局微调”（如候选框高度/行距/字体大小/亮暗色模式），把键盘的 adaptiveness（按钮响应/轻触感）作为可选设置。

### 4.2 工具栏/快捷入口
- 参考：搜狗手机版工具栏扩容（30 个 icon + 固定工具栏 + 最近使用）、设置面板清晰化。
- 方向：
  - 将当前“剪贴板”按钮为代表的工具栏做成更灵活的扩展点：可以把表情、回复片段、AI 工具、翻译、换皮肤都挂接到工具栏上。
  - Windows 控制中心把“候选项修正（符合用户码表习惯）”“输入法切换模式”“多设备管理”等工具整合到一个视觉层级明确的设置面板中，避免深层页面。

---

## 五、工程架构与性能（贯穿所有迭代）

### 5.1 引擎与 UI 分层
- 保持 librime 引擎与 UI 层级分离（当前 Windows 用 TSF 是合理的）；Android 侧持续优化输入延迟（JNI 引擎单例、异步预热、增量加载表）。

### 5.2 测试与验收机制
- 当前工程已覆盖大量 Rust/JNI 单元测试；后续可以：
  - 在 Windows 持续做 UI 端 E2E 验证工具（Tauri App 组合测试运行）。
  - 在 Android 上增强集成测试（JNI 集成 + 输入法生命周期模拟式验收），避免键盘打开态、面板切换、跨设备消息等场景回归。

### 5.3 兼容性与更新通道
- 保持 install/upgrade 流程的兼容性；在 NSIS / Tauri 安装器上进一步明确“回退策略”（失败时回退到上一个版本或默认布局），减少更新损坏对用户的影响。

---

## 结语

搜狗的迭代经验告诉我们：输入法的关键不是“表面花哨”，而是把打字、候选、屏幕、跨设备的核心体验做到“顺手”，再加上逐渐增强的辅助功能（AI、语音、个性化），并且在所有设备上保持一致的视觉反馈与操作体验。Shurufa 一步步走，最后会形成一个深度定制化但不过度膨胀的开源输入法体验。

此文档会持续更新，根据工程演进和用户反馈，不断调整优先级与实施细节。

**Windows 设置中心（`platforms/windows-settings`）**

### D2. 第二批追加交付（2026-08-08 深夜批次）

承接 §一/§二/§三/§四遗留：**协议协商**、**AI 帮写** 与 **候选副标** 全部落地。

**core/sync（剪贴板 wire protocol v2，`core/sync`）**
- `Message::Hello` 新增 `features: Vec<String>` 与 `protocol_version: u32`（serde default 1 → 老版本端仍能反解）。
- `Message::ClipText/ClipImage/ClipFile` 新增 `msg_id: Option<String>` + `origin_device_fp: Option<String>`，全部 `#[serde(default)]`。
- 新常量：`FEATURE_MSG_ID_V1`、`FEATURE_LWW_V1`、`PROTOCOL_VERSION = 2`；`peer_supports(features, name)` 判定对端能力。
- `Shared` 新增 `recent_out: Mutex<Vec<(String, i64)>>`（环形 64 槽），记录本端近期发出的 (msg_id, sent_at_ms)。
- `Outbound::Text` 携带 `msg_id`（32 hex chars）+ `sent_at_ms`；`duplex` 收侧运行两级回声剔除：
  - ① `origin_device_fp == 本端指纹` → 直接 skip（强匹配）
  - ② `(msg_id, sent_at_ms ± 5s)` 与 `recent_out` 匹配 → skip（弱匹配，覆盖旧版本端 echo）
- 只有对端 hello 宣告 `msg-id-v1` 时才在 wire 上写 msg_id / origin_device_fp；旧端仍按 v1 协议通讯。

**Windows 桌面（`platforms/windows-host`）**
- 新增 `ai_panel.rs`：Ctrl+Shift+W 呼出 AI 帮写面板（独立窗口类 `ShurufaAiPanel`，与候选人区分）。
  - 状态机：Editing → Pending → Preview / Failed / Misconfigured。
  - Pending 阶段用 `Instant::now` 显示 "思考中…（X s）"。
  - Preview 用 `DT_WORDBREAK` 多行预览 220 字；Esc 关闭，回车粘贴草稿到原前台（先 `set_clipboard_text` + `SetForegroundWindow` 回前台 + `SendInput` 发 Ctrl+V，先抬 Shift 避免变 Ctrl+Shift+V）。
  - Failed 显示 R 键回编辑态；Misconfigured 直接提示用户在系统属性里加 `AGNES_API_KEY`（**key 不入日志/配置/剪贴板，只在请求时读取**）。
  - HTTP 客户端：ureq 2.12，`POST https://apihub.agnes-ai.com/v1/chat/completions`，模型 `agnes-2.5-flash`，`stream=false`，45s 超时；worker 线程跑 + `PostMessageW(WM_AI_DONE)` 回 UI 线程，`Box<(String, Result<String, String>)>` 经 LPARAM 转移所有权。
  - 内置系统提示约束输出 300 字以内可粘贴中文段落。
- `listener.rs` 在消息循环里同时分发 `HOTKEY_ID=1`（历史）和 `HOTKEY_ID=2`（AI）；`main.rs` `mod ai_panel;`。

**Android（`platforms/android/app`）**
- 功能行新增第三个 chip `🪄 AI 帮写`，独立面板 `aiPanel`（不与 historyPanel 共用），布局：标题栏（标题+✕） / `EditText`（IME_ACTION_SEND） / 状态行 / 草稿预览（可选中复制，包 ScrollView） / 底部按钮组（粘贴 + 重试）。
- `readAiApiKey()` 用反射从 `BuildConfig.AGNES_API_KEY` 读；gradle 端 `buildConfigField` 把 `providers.gradleProperty("AGNES_API_KEY").orElse(providers.environmentVariable("AGNES_API_KEY"))` 注入，绝不下落 gradle.properties 入仓。
- `callAgnesChat`：`HttpURLConnection` POST，15s connect / 45s read，请求体直接用 `org.json.JSONObject` 构造（消息结构 = system prompt + user prompt，与 PC 同）。错误区分 HTTP 状态码与网络异常。
- `ioExecutor.execute` 跑网络，`mainHandler.post` 回主线程更新 UI；成功后 `commitAiDraft()` 走 `ic.finishComposingText() → commitText(draft, 1)`，关闭面板回到键盘。
- `onFinishInput` 同时复位 aiPanel（可见性 + 清空状态/草稿），避免下次打开看到上一次失败态。

**Windows TSF（`platforms/windows/src/candidate_window.rs`）**
- `Item` 新增 `comment` 字段（引擎候选附注，雾凇拼音会给 emoji/近义词/词条类别等）。
- `show()` 测量阶段新增 `comment_w`（用 sub_font 实测），叠加进 `text_w` 占住后续槽位避免重叠。
- `paint()` 在主文本右侧 `+2px` 用小号灰字渲染 comment，单行不换行；不与 text 相同的 comment 自动隐藏为 `""`。

### C. 待实测回归（搜狗日志反推，存在可能性但本轮未复现）

这些是在搜狗历史上被反复打回的 bug，与我们现有改动面高度耦合，需要在真机/真宿主验证；**不能合并进主线前必须各跑一次**：

1. **TSF 候选窗在 WIN11 SearchHost.exe / 锁屏 / Start menu 上的跟随**——搜狗 2023-2025 至少修过 3 次；当前候选窗锚点取 `composition.GetRange + GetTextExt`，未做 SearchHost.exe 专项回归。
2. **亮暗主题切换时不重启输入法的场景下 IME 子面板（剪贴板/图片预览）未刷新**——本轮 B10 已覆盖键盘根视图；子面板（历史/预览）是同一 `palette` 引用但 `onConfigurationChanged` 里只 `setInputView(onCreateInputView())`，子面板已有内容会重建，属预期行为。
3. **游戏 / 全屏 DXGI 抢占场景首键丢失**——本次 Shift/Ctrl./CapsLock 都加了编辑会话收尾，理论上缓解；需在 Dota2/CSGO/原神实机验证。
4. **锁屏界面输入法状态泄露（搜狗 2024.8 锁屏提权）**——TSF 在 secure desktop 不应响应快捷键；我们只在 `is_ime_key` 接管 print-letter，未做 `ITfThreadMgr::IsThreadFocus` 检查。回归时需验证锁屏 + Win+L + UAC 提示下 Shift/CapsLock 不会被我们的 toggle 吞掉。
5. **图片附件 >8MB PNG 在多设备 + 弱网叠加下的卡顿**——`SyncBridge.maxImageBytes()` 已有上限；`commitImage` 走 ioExecutor；但实机图床大图 PNG 与发送队列叠加未压测过。
6. **`options.json` 跨进程并发写**——设置中心和 TSF 都在写；当前是先写 .tmp 再 rename 的原子替换，但若两端同时写仍可能丢一端改动；低概率，未做 advisory lock（搜狗设置中心也同样并发模型，接受现状）。
7. **候选长按菜单在 Android 12 以下 AlertDialog 弹起需要前台 Activity**——实测 IME 的 AlertDialog 在 IME context 下是允许的，但少数 ROM 会拒绝；需要回归。

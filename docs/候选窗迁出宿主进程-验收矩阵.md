# 候选窗迁出宿主进程——S4 验收矩阵

> 目标：在具备真实 Windows 测试环境时，按本矩阵逐项执行；自动项用脚本，
> 手动项记录“步骤 / 预期 / 实际 / 证据”。避免“有环境但不知道测什么”。

## 0. 环境准备

| 项 | 要求 | 检查方式 |
|---|---|---|
| OS | Windows 10 21H2+ / Windows 11 | `winver` |
| 分辨率/多屏 | 至少 1 台；多显示器场景需 ≥2 台（扩展模式） | 设置 → 系统 → 屏幕 |
| DPI | 100% / 125% / 150% / 200% 至少各验一次 | 设置 → 缩放 |
| 账号 | 普通用户 + 管理员各验一次 | 管理员记事本场景 |
| RDP | 如可用，远程桌面连入验一次 | `mstsc` |
| 输入法 | 已注册 Shurufa TSF；`options.json` 可改 `candidate_window` | `regsvr32` / 设置 |
| 依赖 | Rust 构建产物、`shurufa-ui.exe`、`shurufa-host.exe` | `target\debug\*.exe` |
| 自动化 | Python 3 + pywinauto | `python -m pip install pywinauto` |
| 读屏 | NVDA 或 Windows 讲述人（UIA 验证用） | 可选 |

## 0.4 单屏环境（当前机器）先测这些

如果你只有单屏，先聚焦本机可完整验证的项：

- A1–A5：hosted 基本链路（显示/点击/数字/翻页/Esc）；
- B1–B3：杀 `shurufa-ui` 回退内置、重启恢复；
- C1–C2：两个编辑器多客户端不串台；
- E1：管理员应用 hosted 可用；
- E2：全屏应用自动回退内置（可用最大化窗口近似验证）；
- E4：锁屏/安全桌面；
- E5：NVDA/讲述人读取候选文本（UIA Name）；
- F1–F3：长时间稳定性/快速连击/反复重启。

单屏暂时无法完整验证，后续有多屏/远程环境再补：

- D1–D4：多显示器 + 不同 DPI 拖屏；
- E3：RDP 远程桌面；
- 多屏下的候选窗跟随/坐标。

`scripts/test-cand-acceptance.py` 会自动识别单屏并输出上述裁剪清单。

## 0.5 便携工具（无需 Python/环境）

```powershell
# 构建
cargo build -p shurufa-host --bin shurufa-cand-tool

# 直接跑自检 / 示例 / 环境信息
target\debug\shurufa-cand-tool.exe --selftest
target\debug\shurufa-cand-tool.exe --demo 5
target\debug\shurufa-cand-tool.exe --info
```

单 exe 可拷到任意 Windows 机器，不依赖 Python/pywinauto。

## 1. 自动化回归（有环境即可先跑）

```powershell
# 构建
cargo build -p shurufa-host --bin shurufa-ui
cargo build -p shurufa-tsf

# 协议层
cargo test -p ime-ipc
cargo test -p windows-ipc --test cand_e2e

# UI 宿主自检
target\debug\shurufa-ui.exe --cand-selftest

# pywinauto 语义冒烟
python scripts\test-cand-ui.py --exe target\debug\shurufa-ui.exe

# 交互（点击选词 + 滚轮翻页）
python scripts\test-cand-interact.py --exe target\debug\shurufa-ui.exe

# 故障注入
python scripts\test-cand-faults.py --exe target\debug\shurufa-ui.exe

# 稳定性（反复 Show/Hide + 反复重启）
python scripts\test-cand-stability.py --exe target\debug\shurufa-ui.exe --rounds 2

# 管道断开清理（旧客户端断开后隐藏，新客户端恢复）
python scripts\test-cand-disconnect.py --exe target\debug\shurufa-ui.exe
```

预期：全部 exit 0。

## 2. 功能验收矩阵

### A. hosted 基本链路

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| A1 | `options.json` 设 `candidate_window=hosted`，重启 shurufa-host/TSF | 候选窗由 `shurufa-ui.exe` 创建；`shurufa-ui` 进程存在 | 任务管理器 / 窗口类 `ShurufaCandWin` |
| A2 | 记事本输入 `nihao` | 候选窗显示“1.你好 2.拟好…”，位置贴近光标 | 截图 + pywinauto 读取标题 |
| A3 | 鼠标点击候选“你好” | 上屏“你好”，候选窗隐藏 | 编辑器文本 |
| A4 | 数字键 1/2 选词、PageDown/Up 翻页 | 与内置路径行为一致 | 编辑器文本 + 候选页变化 |
| A5 | Esc 取消组合 | 候选窗隐藏，preedit 清空 | 编辑器文本 |

### B. builtin 回退与恢复

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| B1 | hosted 模式下杀掉 `shurufa-ui.exe`，继续输入 | 输入不中断，候选窗回退内置绘制 | 窗口类仍可见但进程为 TSF 宿主 |
| B2 | 重启 `shurufa-ui.exe`，继续输入 | 候选窗自动回到 hosted | 窗口属主进程变为 `shurufa-ui.exe` |
| B3 | 断开管道后重连 | 无残留旧候选窗，新帧正常显示 | 窗口数量 |

### C. 多客户端

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| C1 | 打开两个记事本，各自输入拼音 | 两个独立候选窗，互不串台 | 每个窗口标题对应各自候选 |
| C2 | 分别点击/翻页 | 各自上屏正确 | 两个编辑器文本 |

### D. 多显示器与 DPI

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| D1 | 副屏打开编辑器输入 | 候选窗出现在副屏光标附近 | 截图 |
| D2 | 缩放 125%/150%/200% 下输入 | 候选窗大小/字号按 DPI 缩放，不错位 | 截图 |
| D3 | 不同 DPI 的两个屏间拖动窗口后输入 | 候选窗跟随当前屏，无偏移 | 截图 |
| D4 | 宿主 DPI 感知为 V1/unaware 的应用 | 候选窗坐标仍正确（hosted 按物理像素） | 旧版对比 |

### E. 特殊环境

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| E1 | 管理员记事本输入 | hosted 候选窗正常，点击/翻页可用 | 截图 |
| E2 | 全屏应用（游戏/视频）输入 | 自动回退内置候选窗，不被遮挡 | 截图/日志 |
| E3 | RDP 远程桌面输入 | 候选窗跟随光标，无残留 | 截图 |
| E4 | 锁屏/安全桌面 | 候选窗不弹出，输入不异常 | 手动确认 |
| E5 | UIA 读屏（NVDA/讲述人）聚焦候选窗 | 能读到候选文本（`cand_uia` Name） | 读屏输出 |

### F. 稳定性/性能

| # | 步骤 | 预期 | 证据 |
|---|---|---|---|
| F1 | hosted 模式连续输入 10 分钟 | 无崩溃、无候选窗残留、内存稳定 | 任务管理器 |
| F2 | 快速连续击键 | 候选窗不闪烁、无跨进程明显延迟 | 录屏 |
| F3 | 杀掉 ui 后反复重启 10 次 | 每次都能恢复 hosted | 脚本/日志 |

## 4. 自动环境预检脚本

运行 `python scripts/test-cand-acceptance.py` 可先检查环境并跑自动项：

- 显示器数量、分辨率、当前缩放（尽量读取）；
- pywinauto 是否安装；
- 构建产物是否存在；
- 自动执行 `test-cand-ui.py` 与 `test-cand-faults.py`；
- 输出手动验收清单提醒。

# M4 安卓端验收：手机接收电脑剪贴板

安卓同步接入。安全模型与桌面一致（自签证书、六位确认码、TLS 1.3
双向认证 + 指纹钉扎）。安卓端取舍：关闭 mDNS（省电策略下不可靠），
手机作发起端输入电脑 IP 直连；入站条目走轮询。

产物：`platforms/android/app/build/outputs/apk/debug/app-debug.apk`
（约 16MB，因内置 tokio+rustls+ring）。

## 前置

1. 电脑与手机同一 Wi-Fi
2. 电脑运行 `scripts/start-host.cmd`，`shurufa-host devices` 记下电脑 IP
   （或 `ipconfig` 查无线网卡 IPv4）

## 配对

1. 手机装 APK，打开「Shurufa 输入法」应用图标（进配对页）
2. 输入电脑 IP，点“配对”
3. 手机与电脑几乎同时显示**六位确认码**（电脑弹对话框，手机显示大字）
4. **核对两码一致**：手机点“一致，确认”，电脑点“是”
5. 手机配对页“已配对设备”出现电脑名；电脑 `shurufa-host devices` 出现手机

## 同步验收

1. 在电脑任意处复制一段文本
2. 手机上呼出 Shurufa 键盘（任意输入框），键盘顶部橙色条显示
   「来自 <电脑名>：<内容预览>（点此上屏）」
3. 点该条 → 文本上屏到当前输入框

## 已知边界

- **仅电脑→手机方向自动可用**：安卓 10+ 后台应用不可读剪贴板，手机端
  用户在别处的复制无法被捕获；手机→电脑需在键盘内主动触发（预留
  `SyncBridge.nativeSendClip`，UI 按钮后续加）
- **手机端无本地历史库**：收到的内容仅在键盘顶部提示一次并上屏，不入库
  （手机侧历史面板为后续工作）
- 键盘活跃（弹出）时才轮询接收；收起后不接收，符合安卓省电约束
- 仅文本；图片/文件不同步
- 手机重启或长时间后台后，需再次呼出键盘触发同步服务启动

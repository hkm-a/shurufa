# M10 评估报告（无障碍 / 语音 / GB18030 / 生僻字）

> **历史快照**：本报告记录该里程碑当时的验收情况，**不代表当前状态**。
> 当前质量信号以 CI 为准（见 README 徽章与 `scripts/` 下的四个门禁脚本）；
> 定位与理由见 [文档管理](文档管理.md) §9。

> 评估日期：2026-08-18 ｜ 对应计划：[开发计划](开发计划.md) M10（P2 项：12.0 无障碍、8.2a 语音、14.4 GB18030、7.5 生僻字）
> 结论先行：四项中三项已有关键兜底/可落地路径，读屏为中等工作量工程，均给出分阶段建议。

## 一、M10-5 生僻字字库扩充（搜狗 7.5，P2）

**现状盘点**
- **Unicode 输入兜底已实装**（2026-08-18）：`schemas/lua/unicode.lua` —— 输入 `U + 十六进制码点` 直接产出对应字符（U4F60→你、U1F600→😀、U03B1→α）。**一切 Unicode 码位（含 CJK 扩展区 A-G）都可输入**，不依赖词库收录。这是生僻字输入的最短路径，且已随 rime_ice 方案部署、引擎集成测试覆盖。
- **rime-ice 大字库**：仓库使用 rime-ice 2026.06.30 字表（schemas/rime-ice-2026.06.30.json 快照），常用生僻字（扩展 A/B 常见字）在词库内。

**结论**：生僻字**输入**能力已闭环（U+ 兜底 + 大字库）；"扩充"的剩余价值在于**常见扩展区字按拼音可打**（如 U+9FA6 龦 等），这依赖词库收录而非引擎能力。

**建议**（按收益排序）
1. 保留 U+ 输入兜底（已交付）——扩展区字全量拼音词库体积大（数万条）、拼音命中率低，性价比低；
2. 后续可做"生僻字常用 500 表"词库（按使用频率收录扩展区常见字拼音），作为可选词库包挂载（与 M10-1 专业词模式的词库包机制复用）；
3. 不追求 GB18030-2022 全量字库（见第四节）。

## 二、M10-2 无障碍读屏支持（搜狗 12.0，P1）

**现状盘点**
- Windows 候选窗 / 历史面板 / AI 面板均为自绘窗口（GDI / D2D / DComp 三后端），**未实现 UI Automation（UIA）Provider** —— 屏幕阅读器（NVDA/讲述人）读不到候选内容与面板状态。
- TSF 文本服务本身参与编辑控件（Composition/文档），读屏对"正在上屏的文本"仍可经编辑控件读到（输入法不阻断）。

**结论**：读屏是**中等工作量工程**，不是开关项。核心 = 为候选窗暴露 UIA 文本 Provider（ITextProvider + AutomationElement，随候选更新触发 Name/Text 变化事件），读屏即可朗读候选与选择。

**建议（分阶段）**
- **v1.1（本轮不阻塞）**：TSF 提交上屏路径已完整（commit → 文档插入），读屏可读到最终上屏文本——先交付"上屏可达"，并在 CHANGELOG 说明；
- **v1.2 计划**：候选窗 UIA Provider（候选文本/高亮索引/按键说明），随候选刷新兴起变化事件；Android IME 侧用 AccessibilityNodeInfo 暴露候选列表（工作量中等，与 Windows 并行）。

## 三、M10-3 语音输入（搜狗 8.2a，P2）

**现状盘点**
- 语音转写为 dev-stub（Ctrl+Shift+S → 固定文本"你好，世界。"），框架已就位：speech 面板、热键注册、设置中心开关（speech.enabled / hotkey_enabled）。
- 引擎通道：host 已有 Agnes API 调用链（ai_panel::call_agnes，AGNES_API_KEY 环境变量），可复用做**云端语音转写**。

**结论**：两条落地路径评估如下——**推荐云端优先（P2 试点），本地 Whisper 留后续**。

| 路径 | 成本 | 延迟/依赖 | 建议 |
|---|---|---|---|
| 云端转写（复用 Agnes/任一 OpenAI 兼容 ASR） | 低（新子命令 + 音频采集 + 上传） | 需网络 + API 额度；约 1-3s | ✅ 先做试点（复用 AGNES_API_KEY 通道） |
| 本地 Whisper（whisper.cpp） | 中高（模型 ~50MB 起、CPU 推理、集成 cpp 或子进程） | 离线可用；约 2-5s/句 | 🔶 后续版本（v1.2+） |

**建议**：v1.1 接入云端转写试点（设置中心语音页选"云端（需 API Key）"，采集 3-10s 音频 → 转写 → 插入文档）；本地 Whisper 列入 v1.2 评估。

## 四、M10-4 GB18030-2022 全量汉字（搜狗 14.4，P2）

**现状盘点**
- GB18030-2022 强制汉字约 8.7 万码位（含 CJK 扩展 A-G），其中**绝大多数是无人使用的生僻字/历史字形**，无常用拼音。
- librime 编码本身支持 UTF-8 码点输入（U+ 兜底已覆盖全部码位），引擎侧无缺口。
- 全量字库的代价：字表体积（数 MB）、拼音词库覆盖极低、对日常输入无增益。

**结论**：**不建议全量字库**。合规与实用性权衡：
- "能输入任何 GB18030-2022 汉字"——U+ 输入兜底已满足（任意码位）；
- "按拼音打出全部扩展区字"——不现实（多数无读音共识）；
- 若需**展示/检字**能力（如部件查字），search.lua 辅码反查已提供部件拆字路径（M7 已实装），可继续深化。

**建议**：保留 U+ 兜底 + 大字库现状；在 M10-1 词库包机制落地后，把"常用生僻字 500"与"GB18030 合规清单"作为可选词库包发布，按需挂载。

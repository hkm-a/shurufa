# 发布与灰度管道

> 目标：稳定版走 tag 发布，日常 main 自动产出 Canary 预发布包，后续可按需扩展灰度比例。

## 通道

| 通道 | 触发 | 版本 | 发布物 |
|---|---|---|---|
| Stable | 推送 `v*` tag | `version.json`（如 `0.8.0`） | `FOX-Setup-<version>.exe` + `.sha256`，GitHub Release |
| Canary | push main / 手动触发 | `<当前版本>-canary.<sha>` | 同名 `FOX-Setup-*.exe`，更新到 `canary` 预发布 Release |

## Canary 工作流

`.github/workflows/canary.yml`

- 每次 push 到 `main` 自动构建 Windows 安装器；
- 也可在 GitHub Actions 页面手动触发；
- 版本号派生：`version.json` 的版本 + `-canary.<commit短sha>`；
- 产物持续更新到同一个 `canary` Release（预发布），不产生大量正式 Release。

## Stable 发布

沿用现有流程：

1. `scripts/set-version.ps1 -Version X.Y.Z -VersionCode N`
2. 更新 CHANGELOG
3. 打 tag 推送触发 `.github/workflows/release.yml`
4. 自动创建正式 GitHub Release

## 灰度核心（已落地）

- `core/update`（update-core）：
  - `UpdateManifest` JSON 解析/序列化
  - 版本比较（支持 `-pre`）
  - 按 `machine_id + channel` 稳定哈希分桶，`rollout_percent` 决定是否更新
  - 单测覆盖：解析、版本、全量/未知渠道、灰度比例、同机器稳定性
- `scripts/generate-update-manifest.ps1`：生成 `dist/update.json`

### update.json 示例

```json
{
  "channels": {
    "stable": {
      "version": "0.8.0",
      "url": "https://example.com/FOX-Setup-0.8.0.exe",
      "sha256": "abc...",
      "rollout_percent": 100
    },
    "canary": {
      "version": "0.8.0-canary.abc123",
      "url": "https://example.com/canary.exe",
      "sha256": "def...",
      "rollout_percent": 10
    }
  }
}
```

## 后续接入点

- 在安装器/更新器里加入 channel 字段（stable / canary / beta）；
- 客户端定时拉取 `update.json`，调用 `update_core::should_update` 决定是否提示更新；
- 更新流程：下载安装包 → 校验 sha256 → 静默安装/引导安装。

## 本地验证 Canary 打包

```powershell
pwsh -NoProfile -File scripts\build-installer.ps1 -VersionOverride "0.8.0-canary.local"
```

不会改动 `version.json` / `set-version.ps1` 派生点。

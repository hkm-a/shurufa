# 候选窗迁出宿主进程——迁移方案（阶段 6 候选）

> 状态：设计定稿，未实施。前置条件已满足（`core/ime-policy` 已建成，UI
> 层与协议已解耦，`shurufa-ui` 面板进程已常驻）。本方案来自
> [架构审视与选型替换报告](架构审视与选型替换报告.md) §7.5：方向正确
> （weasel 的 `WeaselServer.exe` 同款模型），但锚点/焦点/合成时序需要重做，
> 必须作为独立阶段灰度推进，不允许一步切换。

## 1. 背景与动机

当前候选窗在 TSF DLL（`platforms/windows/src/candidate_window.rs`，约 2,700 行）
里，**每个文本输入宿主进程各自加载一份**。已知问题根因都在这个模型上：

- **多显示器 / DPI**：宿主进程的 DPI 感知决定候选窗坐标映射，每个 app 的
  感知策略不同（PerMonitor V2 / V1 / unaware），同一台机器上不同 app 的
  候选窗偏移表现不一致。
- **崩溃面**：候选窗绘制代码跑在用户最敏感的应用（浏览器/IDE）进程里，
  任何绘制崩溃直接带走宿主应用。
- **内存**：每个宿主一份皮肤 + GDI 资源。
- **升级**：DLL 升级受"文件被占用"约束（安装器已被迫做唯一文件名回退），
  而独立进程的 exe 不受 TSF 加载锁定影响。

weasel 的解法是候选服务进程（`WeaselServer.exe`）：TSF 侧只采集事件与
上屏，候选 UI 全部在服务进程绘制。

## 2. 目标架构

**候选 UI 全部迁入 `shurufa-ui`**（已常驻、已是 UI 故障域、已
PerMonitorV2 DPI 感知、已由 supervisor 看护重启），不新建进程：

```
┌ app 进程（N 个）──────────────┐      ┌ shurufa-ui（1 个）─────────────┐
│ TSF DLL                       │      │ CandidateWindowHost            │
│  ├ 按键 → algo 管道（不变）    │      │  ├ 每 clientId 一个候选窗      │
│  ├ 组合/上屏（不变）           │ IPC  │  ├ 皮肤（windows-skin 复用）   │
│  └ CandClient ────────────────┼─────►│  └ 点击/翻页 → 回发同连接      │
│     上行：Show/Move/Hide      │ 管道  │ CandServer（多连接并发）       │
│     下行：Select/PageTurn     │      │                                │
└───────────────────────────────┘      └────────────────────────────────┘
```

- **algo 管道与组合数据流完全不动**：候选数据仍由 TSF DLL 从 algo 取回，
  迁移只改"取回后在哪里画"。
- 新增一条**候选窗事件管道** `\\.\pipe\shurufa-cand`：TSF DLL 是 client
  （每宿主一个连接），shurufa-ui 是 server（多连接，模式与 `windows-ipc`
  的 algo server 相同，帧编解码复用 `core/ime-ipc`）。

## 3. 协议草案（core/ime-ipc 新增 DTO，平台无关）

上行（TSF → ui）：

```rust
pub enum CandEvent {
    /// 显示/刷新候选：clientId（宿主连接标识）、组合串、候选页、
    /// 高亮索引、光标屏幕矩形（已按宿主 DPI 换算为物理像素）、宿主 DPI。
    Show { client_id: u32, preedit: String, candidates: Vec<Candidate>,
           highlighted: usize, caret_rect: (i32, i32, i32, i32), dpi: u32 },
    /// 翻页/滚动后的新页（数据同上，避免 ui 侧持有会话状态）。
    Page  { client_id: u32, candidates: Vec<Candidate>, page_no: usize, is_last: bool },
    Hide  { client_id: u32 },
}

pub enum CandCommand {  // 下行（ui → TSF，同一连接回发）
    Select { client_id: u32, index: usize },   // 数字键/点击/空格选词
    PageNext { client_id: u32 }, PagePrev { client_id: u32 },
    Hover { client_id: u32, index: usize },    // 高亮跟随（可选）
}
```

要点：

- **ui 侧无会话状态**：每次 Show/Page 都带全量候选，ui 崩溃重启后 TSF 下
  一次按键自然恢复显示——这是"面板进程崩了不影响输入"的关键。
- `caret_rect` 由 TSF 在 edit session 里取（`ITfContextView::GetTextExt`），
  **乘宿主 DPI 缩放换算为物理像素**后再发；ui 进程按自己的 PerMonitorV2
  感知直接用物理坐标，从根上消灭"每个 app 一套偏移"。

## 4. 关键风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 锚点 | GetTextExt 需在 edit session 内；部分应用返回屏幕坐标未含 DPI | 迁移期同时打印宿主进程 DPI 感知，验收矩阵覆盖 V2/V1/unaware 三类 |
| 焦点 | 候选窗必须永不抢焦点（否则打断合成） | `WS_EX_NOACTIVATE \| WS_EX_TOPMOST \| WS_EX_TOOLWINDOW`，鼠标用 `WS_EX_TRANSPARENT` 除命中区外；weasel 同款 |
| 合成时序 | 跨进程一帧延迟，快速连续击键时候选滞后于 preedit | Show 全量推送即可丢弃中间帧（ui 侧 per-client 只保留最新）；按键期间用户视线在文本而非候选，可接受 |
| 提权宿主 | 管理员应用的 TSF 连接普通权限 ui 的管道：UIPI 不拦命名管道，但回发 PostMessage 无此问题（全走管道） | 管道 ACL 与 algo 管道一致（`PIPE_REJECT_REMOTE_CLIENTS` + 当前用户 SID），验收矩阵含管理员记事本 |
| 全屏应用 | 游戏全屏候选窗被挡/闪 | 检测宿主全屏（TSF 侧拿前台窗口矩形比对），全屏时回退内置绘制（见迁移 S3 灰度开关） |
| ui 崩溃 | 候选消失但输入必须继续 | ui 侧零会话状态（§3）+ TSF 侧连接断开自动回退内置精简候选条 |

## 5. 迁移步骤（每步独立可合并、可回滚）

1. **S1 协议层**：`core/ime-ipc` 增加 `CandEvent`/`CandCommand` DTO 与帧
   编解码测试（零平台依赖，进 core-portable 门禁）；`platforms/windows-ipc`
   增加 cand 管道的 server/client 传输与 e2e 测试（模式照抄 algo 管道）。
2. **S2 ui 侧宿主**：`shurufa-ui` 增加 `CandidateWindowHost`：多 client 窗口
   池、无焦点顶层窗、皮肤复用 `windows-skin`、点击/滚轮回发命令。单测 +
   人工验收单显示器。
3. **S3 TSF 双路径灰度**：`candidate_window.rs` 增加 `CandClient` 出口，
   options.json 新增 `candidate_window: "builtin"（默认） | "hosted"`；
   `hosted` 时上屏/选词逻辑改走管道回发。内置绘制路径保留。
4. **S4 验收矩阵**（人工，双显示器 + 三类 DPI 感知 + 管理员窗口 + 全屏 +
   RDP）：两路径并跑一周（本机日用即灰度）。
5. **S5 默认翻转**：默认 `hosted`；内置路径降级为全屏/管道故障 fallback，
   观察一个版本后删除内置绘制（约 -1,500 行，迁出的部分进 ui）。

## 6. 工作量与排期建议

S1 约 1 天（协议+传输+测试），S2 约 2-3 天，S3 约 2 天，S4 一周灰度，
S5 半天。合计 5-6 个工作日 + 灰度期。**建议作为独立阶段（阶段 6）整段
排期**，不与其它改动混批；S1（纯协议+测试，零行为变化）可先行合入。

## 7. 明确不做的

- 不改 algo 管道协议与组合数据流（`ProcessKey/Commit/Context` 原样）。
- 不把按键事件迁出 TSF（那是输入延迟敏感路径，多一跳 IPC 得不偿失）。
- 不引入 weasel 源码（GPL-3 与本仓兼容，但其 server 是 C++/Win32 体系，
  移植不如按本方案用现有 Rust 栈重写来得干净——报告 §2 复用原则）。

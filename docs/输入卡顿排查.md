# 输入卡顿排查指南

> 面向实机"打字莫名卡顿"的系统性排查手册。每次修复的根因与验证证据都沉淀在此，
> 避免重复排查。更新：2026-08-16。

## 一、先分清卡顿类型

| 表现 | 最可能层 | 首要动作 |
| --- | --- | --- |
| 每键稳定粘滞（~10ms+） | 引擎/渲染热路径 | 跑延迟分析（见下） |
| 间歇性、无规律"莫名其妙"卡 | CPU 降频 / 系统偶发 | 查 IFEO 高优先级、对照系统级问题 |
| 首键卡、后续流畅 | 引擎首次会话/词典加载 | 安装后预热（安装器已内置） |
| 超长串输入时卡死 | translator 查找爆炸 | 超长组合自动清空（已内置 64 码防护） |
| 休眠唤醒后第一次输入 5-10s | Windows 11 系统级 | 对照微软已知问题（见文末） |

## 二、延迟分析（常驻打点）

2026-08-16 起按键→上屏延迟（LAT 行）**默认写入** `%TEMP%\shurufa-tsf.log`
（走内存缓冲批量落盘，零热路径 I/O）。分析：

```powershell
python scripts\analyze-latency.py              # 全部延迟分布（p50/p90/p95/p99/max）
python scripts\analyze-latency.py --last 500   # 最近 500 次
python scripts\analyze-latency.py --min-ms 50  # 只看超过 50ms 的尖峰（含时间戳）
```

参考基线（本机 150% 缩放 + 雾凇词库实测 2026-08-16）：
- 提交上屏 p50 ≈ 11ms，p90 ≈ 11.5ms，无尖峰 → 引擎/渲染正常
- 若 p95 明显抬升或出现 >50ms 尖峰 → 按第三节定位

关闭打点：设环境变量 `SHURUFA_DISABLE_LATENCY_LOG=1`（仅需时开，默认关）。

## 三、已知根因与修复对照

### 1. 每键同步磁盘 I/O（已修，2026-08-16）
- 现象：快速打字时每键 ~3ms 粘滞，磁盘抖动时偶发数十 ms。
- 根因：TSF 热路径每次按键写 2 次日志文件（同步 append）+ 候选窗重读皮肤文件。
- 修复：`debug_log` 改内存缓冲 + 后台 500ms 批量落盘；皮肤加载加 mtime/长度缓存。
- 验证：`cargo test -p shurufa-tsf` 新增缓存行为单测。

### 2. CPU 功耗降频（weasel#1250 同类）
- 现象：间歇性、无规律卡顿；空闲一会儿后首键明显慢。
- 根因：Windows 功耗管理把空闲的算法服务进程压到 0.5-1GHz，按键后频率爬升慢。
- 修复：安装器（管理员）写 IFEO PerfOptions 高优先级——
  `HKLM\...\Image File Execution Options\shurufa-algo.exe\PerfOptions`
  `CpuPriorityClass=3`（High），host 同理。卸载时清除。
- 自查：任务管理器 → 性能 → CPU 频率，输入时是否 <1GHz；设置已生效则进程
  优先级列显示"高"。

### 3. 超长输入串导致引擎爆炸（weasel#649 同类）
- 现象：误触/粘贴大量字母时卡死。
- 根因：librime translator 在超大音节图上查找，内存/CPU 暴涨。
- 修复：算法服务侧 ProcessKey 前检查组合长度，≥64 码自动清空组合（超长转
  纯字母直通，与微软输入法同思路）。正常整句输入（21 码左右）零影响。
- 注意：不用 `speller/max_code_length` 硬限制——会截断正常长句输入。

### 4. 引擎首次加载成本（已由安装器预热）
- 现象：安装/词库更新后第一次输入卡。
- 修复：安装器步骤 9 启动 host 后做一次 IPC 往返（CreateSession + ToggleAscii），
  把会话/词典加载移到安装收尾。

## 四、系统级偶发延迟（先排除）

Windows 11 已知问题（2026-05/08 微软 Q&A 多帖）：
- **休眠唤醒后第一次输入偶发 5-10 秒延迟**，微软拼音/日文 IME 同样中招。
- 任何需要候选窗的 IME 都可能触发，仅英文输入法正常。
- 若用户卡顿表现为"休眠唤醒后首输入秒级延迟"，属系统级，非输入法缺陷；
  可先切换输入法复测确认。

另外注意：TSF 输入法是**进程内加载**的，更新 DLL 后**已运行的应用仍持有旧
副本**，必须重启应用/注销重登才生效（explorer 持锁时尤其明显）。

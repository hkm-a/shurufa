# 发布流程

Shurufa 的版本与发布由 `version.json` 驱动；任何版本必读该文件后再执行 bump。

## 1. Bump 版本

```powershell
pwsh -NoProfile -File scripts\set-version.ps1 -Version 0.4.2 -VersionCode 11
```

脚本会同步写入 `installer\shurufa.nsi`、`platforms\windows-settings\tauri.conf.json`、`platforms\windows-settings\package.json` 与 `platforms\android\gradle.properties` 兜底行，并在写入后强制校验一致。`versionCode` 只会单调递增（Android 要求），版本名遵循语义化。

## 2. 填写 CHANGELOG

在 `CHANGELOG.md` 顶部追加 `## [0.4.2] - YYYY-MM-DD` 段落，按 新增/修复/变更/废弃 组织条目，引用相关提交或 issue。

## 3. 本地全量验证

```powershell
cargo test --workspace --locked
pwsh -NoProfile -File scripts\build-installer.ps1 -Sign      # 签名可在无证书机器省略 -Sign
.\scripts\build-android.cmd
```

`build-installer.ps1` 会先跑 `set-version.ps1 -Check`，不一致直接失败；`-Sign` 依赖环境变量
`SHURUFA_SIGN_PFX`（证书路径）与 `SHURUFA_SIGN_PASSWORD`。未配置时会打印醒目警告，开发自测可忽略，
正式分发**必须**签名，否则 SmartScreen / 杀软会拦截输入法安装器。

## 4. 打 tag 发布

```bash
git add -A
git commit -m "chore(release): v0.4.2"
git tag -a v0.4.2 -m "v0.4.2"
git push origin main v0.4.2
```

tag 推送触发 `.github\workflows\release.yml`：先跑版本一致性校验，再并行构建
- `FOX-Setup-<version>.exe` + `.sha256`
- `shurufa-<version>-<code>-debug.apk`

最后自动创建 GitHub Release，从 `CHANGELOG.md` 提取本版本段落作为正文。

## 5. 失败回退

- **安装器回退**：安装中途失败会中止并保留已写入的文件；重新运行上一版本的
  `FOX-Setup-<version>.exe` 覆盖安装即可回到旧版（安装器每次都会先停旧进程并
  重新注册 TSF，详见 `installer/shurufa.nsi`）。
- **CI 失败**：删除 tag 修好后重打同名 tag；release 草稿可被重复覆盖，产物以最新 attachment 为准。
- **本地版本错写**：手工把 `version.json` 改回旧值并 `set-version.ps1 -Check` 校验其余派生点是否已回滚。

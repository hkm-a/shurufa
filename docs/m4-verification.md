# M4 验收：跨设备剪贴板同步（桌面端）

同步核心在 `core/sync`，桌面端接入在 `shurufa-host`。本轮交付桌面
↔ 桌面的完整链路；安卓端接入为后续工作。

安全模型：每台设备自签证书，SHA-256 指纹即身份；配对用六位确认码
人眼比对（KDE Connect 模式），此后 TLS 1.3 双向认证 + 指纹钉扎。
传输为 TCP + rustls（架构初稿的 QUIC 见 architecture.md 的偏离说明）。

## 1. 自动化验证（已通过）

```bash
cargo test -p sync-core
```

- `身份生成与重载一致`：证书持久化与指纹稳定
- `配对表增删改查与持久化`：peers.json 跨实例可见
- `配对码两端一致且六位`：确认码算法对称
- `消息读写往返`：长度前缀协议
- `配对后双向同步文本`（集成测试）：两个独立身份的服务实例，真实
  TcpListener 绑定 + 真实 TLS 握手 + 配对协议 + **双向文本同步** +
  **未配对第三方收不到广播**（隔离性）

## 2. 双机手动验收（需两台同局域网设备）

当前两端均为桌面时：

1. 两台都启动守护：`scripts/start-host.cmd`
2. 各自查看身份：`shurufa-host devices`（记下对方 IP，同网段）
3. 在设备 A 发起配对：`shurufa-host pair <B的IP>`
   （默认端口 48632，跨端口用 `<IP>:<port>`）
4. A 控制台打印六位确认码；同时 B 弹出配对对话框显示确认码
5. **核对两个确认码一致**后：A 输入 `y` 回车，B 点“是”
6. 双方 `shurufa-host devices` 应列出对方
7. 在 A 复制一段文本 → B 上按 `Ctrl+Shift+V`，历史顶部出现该条，
   来源标记「同步·<A设备名>」；反向亦然
8. 解除：`shurufa-host unpair <指纹前缀>`

## 3. 环境变量（调试/多实例）

- `SHURUFA_SYNC_DIR`：覆盖身份与配对表目录（默认 `%APPDATA%\shurufa\sync`）
- `SHURUFA_SYNC_PORT`：覆盖守护监听端口（默认 48632）

## 已知边界（后续里程碑）

- **文本与图片同步**：图片经 BMP↔PNG 转换跨设备（桌面复制图片→对端入历史库）；
  文件（多文件列表）暂不同步。收到的条目只入历史库、不自动回填系统剪贴板
  （与文本一致，避免"写剪贴板→再被监听器捕获"的回环），从历史面板取用
- **安卓端未接入**：手机与桌面互通是下一步（JNI 已可复用 sync-core）
- **同网段直连**：跨网段需自托管中继（架构文档已规划）
- 单机双守护因共享同一系统剪贴板，无法干净演示“同步”（复制一次两端
  各自都会采集），故同步传输的自动验证以集成测试为准
- 配对确认为人工比对确认码；无自动信任，符合防中间人设计
